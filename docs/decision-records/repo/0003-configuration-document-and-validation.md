# ADR-repo/0003: One Validated JSON Configuration Document, One Parameter Catalogue

| Field          | Value                                                        |
| -------------- | ------------------------------------------------------------ |
| Status         | Accepted                                                     |
| Date           | 2026-10-06                                                   |
| Decision-maker | Nick Warila (repository owner)                               |
| Reversibility  | Medium                                                       |

## Context and Problem Statement

Configuration management renders the configuration for each server. It must be data only, never
code, validated completely before anything changes, and documented by a published schema. Windows
PowerShell 5.1 has no JSON Schema validator, so the published schema and the run-time checks could
drift apart.

## Decision Outcome

- The configuration is one JSON document, read from `-ConfigPath` or the fixed default
  `%ProgramData%\NWarila\WsusMaintenance\maintenance.json`. JSON carries no code and no string in
  it is ever evaluated; a value containing PowerShell expression syntax is refused.
- `Get-MaintenanceConfigurationRule` is the single parameter catalogue: path, type, unit, range or
  allowed values, default and description of every key. Validation, default merging and the
  published JSON Schema (`docs/reference/maintenance.schema.json`, generated by
  `ConvertTo-MaintenanceConfigurationSchema`) are all derived from it, and a test fails if the
  published schema differs from the generated one.
- Validation reports every problem together and corrects nothing: types, ranges, allowed values,
  formats, required keys, case-sensitive unknown keys (error by default, warning when
  `configuration.unknownKeyPolicy` is `Warning`), plain-text secrets, and cross-field rules.
- `schemaVersion` is required; an unsupported version is a configuration error. A deprecated key
  is still read and is reported with its replacement.
- Defaults are the decided values listed in `docs/DESIGN.md` section 8. A value that is specific
  to each deployment (for example the backup destination) has no default and is required while
  its feature is enabled.

### Consequences

- Positive: one place to add or change a parameter; the schema cannot lag the code.
- Negative: cross-field rules live only in code (JSON Schema cannot express them).
